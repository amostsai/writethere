# 手機手寫板

在手機網頁使用內建手寫輸入法，寫好整段後按「傳送」，文字會貼進電腦目前取得焦點的輸入框。

第一版以 **Ubuntu 26.04、GNOME、Wayland** 為目標。手機不需安裝 App，兩台裝置須在同一個區域網路。

## 啟動

本專案資料夾內已建立虛擬環境時，執行：

```sh
./run.sh
```

`setup.sh` 會在 GNOME 應用程式列表及桌面安裝「手機手寫板」圖示，也會在專案內保留 `手機手寫板.desktop`。若檔案管理員將啟動檔當成文字，請使用桌面／應用程式列表的圖示，或在終端機執行 `./run.sh`。啟動檔使用安裝時的絕對路徑，搬移專案後須重新執行 `.venv/bin/python scripts/create_launcher.py --install`。

在新的環境安裝時，先安裝系統套件，再安裝專案：

```sh
sudo apt install python3-venv python3-gi gir1.2-gtk-4.0 iproute2
./setup.sh
```

`setup.sh` 使用系統 Python 建立可存取系統 GTK 的 `.venv`，將 Python 相依套件裝入專案內，不使用 sudo pip。系統還須有可用的 GNOME Portal（`xdg-desktop-portal`、`xdg-desktop-portal-gnome`）。

剪貼簿與鍵盤控制使用同一個經授權的 XDG Desktop Portal 工作階段。本機 GNOME 支援 Clipboard Portal，因此實作改用此介面，避免 `wl-copy` 的暫時視窗後備途徑影響焦點。

## 使用方式

預設連接埠為 **39945**。可在電腦視窗的「連接埠」欄位輸入 1–65535 的整數，按「儲存」；**下次啟動套用**，目前連線不會被中斷。重新啟動後請重新掃描 QR code。

設定保存在 `$XDG_CONFIG_HOME/phone-pad/settings.json`（通常是 `~/.config/phone-pad/settings.json`），僅保存連接埠，不保存驗證碼或輸入文字。若連接埠被其他程式占用，工具會顯示錯誤，不改用隨機埠；請修改、儲存並重新啟動。設定檔無效或無法讀取時，會提示並使用預設 39945。

1. 開啟工具，在系統對話框允許鍵盤控制；若拒絕，按「重新授權」可再試一次。
2. 手機連上同一 Wi-Fi／區網，掃描視窗的 QR code，再輸入電腦顯示的 **6 位數配對驗證碼**。若有多張網卡，選擇手機可連線的位址；網路變更後可重新偵測。
3. 在電腦點選要輸入的位置，保持該軟體取得焦點。
4. 在手機網頁輸入、修改文字，選擇「一般輸入框」或「終端機」，按「傳送到電腦」。
5. 頁面顯示「已送出貼上指令」。文字會保留，方便修改或手動清空。
6. 按「停止並關閉」或關閉視窗，即停止 HTTP 服務並釋放桌面控制授權。

一般模式送出 Ctrl＋V，終端機模式送出 Ctrl＋Shift＋V。工具不額外按 Enter，但**文字本身的換行會保留，貼進終端機時可能執行指令**。目標軟體必須接受對應的貼上快捷鍵。

傳送會取代剪貼簿內容，不自動還原。接收時不切換視窗、不搶焦點；無法辨識游標是否真的位於可編輯欄位。桌面授權對話框本身可能取得焦點，授權完成後請重新點選目標輸入框。

## 連線與失敗處理

- 區網 HTTP 服務使用已儲存的連接埠（預設 39945），每次啟動產生新的邀請憑證與 6 位數驗證碼。QR code 只包含邀請憑證；驗證碼只顯示在電腦視窗，不包含在網址或手機網頁原始碼。
- 同一時間只允許一個配對手機工作階段。第一支成功配對後取得隨機工作階段憑證；第二支即使持有正確 QR code 與驗證碼，也無法占用名額。
- 手機每 2 秒更新連線狀態；30 秒沒有收到其請求時，會釋放名額並更新驗證碼。背景分頁／鎖屏可能停止更新，回來後須使用新碼重新配對，草稿仍保留在頁面中。
- 可從電腦按「中斷手機連線／更新驗證碼」，或由手機按「中斷手機連線」立即換手機。舊工作階段立即失效；正在進行的貼上會先完成。
- 驗證碼錯誤累計 5 次後，暫停接受驗證 30 秒。QR code、驗證碼及配對後的工作階段憑證請只提供給要使用的手機。區網 HTTP 不提供傳輸加密；不自動設定路由器轉送或修改防火牆。
- 如無法連線，確認兩端位於可互通的區網、Wi-Fi 未啟用用戶端隔離，且防火牆允許視窗顯示的 TCP 連接埠。重啟工具會沿用儲存的連接埠，並更新邀請憑證。
- 授權撤銷、桌面斷線時停用傳送。手機背景頁面可能暫停輪詢，回到頁面後會重新檢查狀態。
- 斷線或逾時不會自動重送。結果不確定時，先查看電腦，避免手動重送造成重複文字。
- 同一請求識別碼在本次執行期間最多嘗試一次；失敗也不會以相同識別碼再次貼上。最多保留 10,000 筆識別碼與摘要，滿額後請重啟並重新掃碼。
- 不記錄輸入歷史、不寫入文字日誌；文字僅在手機草稿、處理中的請求及目前剪貼簿中存在。剪貼簿易主或停止服務時釋放工具內的剪貼簿資料。重新整理頁面會清空草稿，同一分頁可保留連線憑證。

## API

所有 `/api/*` 端點須附 Bearer 憑證，跨來源請求會被拒絕。`/api/pair` 使用 QR code 的邀請憑證，其餘端點必須使用配對後的工作階段憑證；邀請憑證不能直接傳送文字。

- `POST /api/pair` → 請求 `{ "code": "012345" }`，成功回應 `{ "session_token": "隨機工作階段憑證", "message": "配對成功" }`。驗證碼必須是字串，以保留開頭的零。
- `POST /api/disconnect` → 釋放目前手機工作階段並更新電腦驗證碼。
- `GET /api/status` → `{ "ready": true, "message": "已授權，可以傳送文字" }`
- `POST /api/send` → `{ "request_id": "唯一識別碼", "text": "原始文字", "mode": "normal" }`；模式為 `normal` 或 `terminal`。
- 文字長度 1–20,000 Unicode 字元，不接受 NUL；請求識別碼為 1–80 個 ASCII 英數字、底線或連字號。
- 傳送回傳 `200` 表示已送出貼上指令，不代表已確認目標軟體接收。`400` 格式錯誤、`401` 驗證碼錯誤／工作階段失效、`403` 跨來源、`409` 已有手機連線／同識別碼不同內容、`429` 配對驗證過於頻繁、`502` 貼上失敗／結果不確定、`503` 未授權／已停止／本次額度已滿。

## 驗證

```sh
.venv/bin/python -m pytest -q
.venv/bin/python -m compileall -q phone_pad scripts tests
desktop-file-validate 手機手寫板.desktop
```

額外的 UI smoke tests 需要 Playwright＋Chrome，以及 Xvfb＋ImageMagick。這些使用模擬桌面後端，不會改變真實剪貼簿或送出按鍵：

```sh
PYTHONPATH=. .venv/bin/python tests/browser_smoke.py
GTK_A11Y=none GDK_BACKEND=x11 PYTHONPATH=. xvfb-run -a .venv/bin/python tests/desktop_smoke.py
```

實際桌面驗收：在瀏覽器、GNOME 文字編輯器與終端機，分別驗證中文、英文、emoji、多行文字、連續傳送及切換焦點；並測試拒絕／撤銷授權、手機斷線與關閉工具後停止服務。終端機多行測試請使用文字編輯程式接收，避免執行測試文字。

互動式實機檢查可執行 `PYTHONPATH=. .venv/bin/python tests/live_desktop_check.py`，在系統對話框允許控制後，測試自己的 GTK、Chrome 與終端機接收視窗；終端機測試時如未取得焦點，請點選標示「手機手寫板：終端機貼上驗證」的測試視窗。只傳送固定範例，終端機接收器不執行指令。
