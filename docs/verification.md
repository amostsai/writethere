# 第一版實作與驗證紀錄

日期：2026-10-19。目標：此機 Ubuntu 26.04.1、GNOME 50、Wayland。

## 已交付

- Python／GTK 4 桌面視窗、區網 IP 選擇與重新偵測、本機 QR code。
- 手機輸入網頁：原生輸入法組字、手動傳送、一般／終端機模式、清空與保留草稿。
- 每次啟動隨機憑證、請求識別碼去重、傳送序列化、斷線不重送。
- 6 位數配對碼、單手機工作階段、30 秒斷線釋放、電腦／手機手動中斷，及驗證錯誤限流。
- Portal 授權、拒絕後重試、撤銷／D-Bus 中斷／Portal 服務重啟後停用。
- 關閉視窗或按停止時終止 HTTP 並釋放桌面會話。
- 專案內虛擬環境、桌面與應用程式列表的啟動圖示、可建置的 Python wheel。

## 實作決定

1. **以 Clipboard Portal 取代 wl-copy。** 程式碼檢查發現本機 wl-copy 可能使用會取得焦點的暫時視窗，與不搶焦點的需求衝突。本機 RemoteDesktop Portal v2 與 Clipboard Portal v1 可提供同一個授權工作階段的剪貼簿與按鍵控制，因此選用這個途徑。成本：需要目前 GNOME 提供的 Clipboard Portal；不擴大支援較舊環境，也不退回可能搶焦點的方式。
2. **有限去重紀錄不淘汰舊識別碼。** 每次啟動最多 10,000 筆請求，滿額停用新請求並提示重啟。只保留識別碼、摘要與結果，不保存文字歷史。成本：長時間大量使用須重新啟動及掃碼。
3. **先在此空白專案建立程式。** 專案沒有既有提交；本次未建立 worktree、提交或推送。
4. **單手機以獨立工作階段憑證識別。** QR 邀請憑證只能發起配對，不能直接傳送文字。第一次驗證成功者占用名額；30 秒沒有手機請求即釋放並更換驗證碼。成本：手機鎖屏或背景頁面暫停更新後，可能需要重新配對。

## 驗證結果

- 完整 pytest：48 passed。涵蓋原有貼上流程，以及 6 位數驗證、開頭零、錯誤限流與恢復、多個同時配對僅一個成功、舊憑證撤銷、心跳續期、斷線釋放、慢速舊請求與進行中貼上的競態。
- 真實 Chrome 手機尺寸頁面：原有輸入流程，另以兩個獨立瀏覽器工作階段驗證錯誤驗證碼、第二支手機被拒絕、手動中斷與換手機、草稿保留，以及舊連線回應延遲到重新配對後才送達的回歸情境。
- Xvfb GTK 視窗：QR 繪製、切換位址、狀態更新與關閉，全部通過。
- 真實 GNOME Portal：經系統對話框授權後，在專用 GTK TextView 連續貼上兩次固定中文、英文、emoji、多行文字，內容正確且維持焦點。
- 真實 Chrome／Wayland：透過 Portal 貼上固定 Unicode 多行文字，內容正確且維持焦點。
- 真實 GNOME Terminal：以 Ctrl＋Shift＋V 貼進 raw-mode 接收器，Unicode 與換行正確，沒有額外 Enter；接收器不執行指令。
- Python 編譯、shell 語法、desktop-file-validate、editable 安裝與 wheel 建置通過。

上述實機檢查使用專用接收視窗；GTK 接收框並非 GNOME Text Editor 應用程式。尚未實測實體手機的相機掃碼、各家手機手寫輸入法、區網防火牆與 Wi-Fi 用戶端隔離。

環境診斷：pytest 出現一筆系統 PyGObject 的棄用警告。`pip check` 另報告從系統繼承的 pynacl 缺少 cffi、gpustat 缺少 nvidia-ml-py；它們不在本專案相依套件內，未更動。
